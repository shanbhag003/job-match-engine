# Job Portal — hourly Naukri scraper & feed

Keeps the Job Match Engine's data fresh. A headless browser visits the configured
Naukri searches, **captures Naukri's own `/jobapi/v3/search` JSON responses**
(no HTML scraping, no forging Naukri's anti-bot token), normalizes each posting to
the app's `Job` schema, enforces the product rules (Navi Mumbai / Mumbai only;
Hybrid / On-site only; **Remote excluded**), and writes `data/jobs.json`. A small
server serves that feed with CORS and refreshes it every hour.

## Why a headless browser

Naukri's search API requires a per-session `nkparam` token generated by its own
client-side JavaScript. Rather than forge it (fragile + against their ToS), the
harvester loads the normal search page in a headless browser and reads the API
response the page itself makes. Robust and low-maintenance.

## Setup

```bash
cd backend
npm install
npm run install-chrome   # download the Chrome build Puppeteer drives (one-time)
```

## Use

```bash
npm run scrape   # one-off: harvest now and write data/jobs.json
npm run serve    # serve GET /jobs.json on :8787 and refresh hourly (cron 0 * * * *)
```

`GET /jobs.json` returns `{ generatedAt, source, count, jobs: Job[] }`.
`GET /health` returns liveness + the feed timestamp.

Tune the search matrix in [`src/queries.js`](src/queries.js) (keywords, cities,
work modes, results per query). Classification (domain/role/city/work-mode) lives
in [`src/classify.js`](src/classify.js) and mirrors the frontend taxonomy.

## Point the frontend at the feed

Build the frontend with the feed URL set:

```bash
# from the project root
VITE_JOBS_FEED_URL="https://your-host/jobs.json" npm run build
```

When `VITE_JOBS_FEED_URL` is unset (e.g. the shared static Artifact), the app uses
its baked-in listings. When set, it fetches the live feed and **falls back to the
baked-in data** if the feed is unreachable — so the UI is never empty. The app
also re-fetches the source once an hour on its own.

## Deploy (any of these)

- **Long-running host** (Render / Railway / Fly / a VPS): run `npm run serve`. Cron
  refreshes hourly; the same process serves the feed. Set `PORT` if needed.
- **Docker**: a Node 20+ image, `npm ci && npm run install-chrome`, CMD `npm run serve`.
  Puppeteer needs the usual headless-Chrome shared libraries.
- **Scheduled CI** (GitHub Actions hourly): run `npm run scrape` and publish
  `data/jobs.json` to any static host / CDN; point `VITE_JOBS_FEED_URL` at it.
  No always-on server required.

## Notes

- Be a considerate scraper: the matrix is small and paced (≈1 req/1.2 s). Keep it
  modest and respect Naukri's terms.
- Individual reqs still expire; the hourly refresh keeps the set current.
- The feed schema matches `src/types.ts` `Job`, so the scorer needs no changes.
